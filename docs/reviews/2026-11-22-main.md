## Summary
This change implements Slice 2 (`0002-data-model`), introducing the core relational database schema, AES-256-GCM envelope encryption for personal LLM provider keys, JSONB virtual file trees for code snapshots, and comprehensive domain queries in `@spark/db` with PGlite integration tests. The schema modeling and cryptographic implementations are clean, well-typed, and adhere closely to Auth.js and Drizzle ORM standards. However, the change is blocked by an unhandled unique constraint collision on empty custom domains in `createDeployment` and a missing database transaction in `saveSnapshot` that violates the governing spec's key atomicity invariant.

## Blockers
### 🔴 Empty string custom domain violates unique constraint on deployment creation, `packages/db/src/queries.ts:532`
**Problem**: In `createDeployment`, `params.customDomain` is processed as `customDomain: params.customDomain?.trim()`. When callers or forms pass an empty string `""` for an optional custom domain, this stores `""` in the database. In PostgreSQL, unique columns permit multiple `NULL` values, but duplicate non-null values including empty strings `""` violate unique constraints (`deployments_custom_domain_unique`).
**Why it matters**: The first deployment created with an empty custom domain succeeds, but any subsequent deployment created without a custom domain crashes with a 500 database error (`duplicate key value violates unique constraint "deployments_custom_domain_unique"`), breaking the deployment creation pipeline.
**Suggested fix**: Convert empty strings to `null` before inserting: `customDomain: params.customDomain?.trim() || null`.

### 🔴 Non-transactional snapshot creation violates spec atomicity invariant, `packages/db/src/queries.ts:226-250`
**Problem**: `saveSnapshot` creates a record in `snapshots` and then updates `projects.currentSnapshotId` as two independent, non-transactional database statements.
**Why it matters**: Spec 0002 explicitly mandates as a Key Invariant: "Saving a snapshot advances projects.currentSnapshotId automatically inside the same database transaction." If a database connection error, server crash, or concurrent update occurs between the two queries, the snapshot is created but `projects.currentSnapshotId` is never updated, leaving the project pointing to a stale snapshot or null with no rollback.
**Suggested fix**: Wrap the `snapshots` insertion and `projects` update within `await db.transaction(async (tx) => { ... })` so that both operations execute atomically.

## Major
### 🟠 `forkedFromProjectId` permits unauthorized cloning of private non-template projects, `packages/db/src/queries.ts:57-67`
**Problem**: In `createProject`, when `forkedFromProjectId` is supplied, the query only verifies that a project with that ID exists. It does not verify that the target project is marked as a template (`isTemplate === true`) or owned by the requesting user (`userId === params.userId`), despite the error message specifically stating `"Template project ... not found"`.
**Why it matters**: Any user who knows or guesses another user's project UUID can fork private projects across tenant boundaries, violating AC-5 and creating an IDOR authorization vulnerability.
**Suggested fix**: Check that the parent project satisfies `isTemplate === true || userId === params.userId`, and throw `NotFoundError` if neither condition is met.

### 🟠 Concurrency race condition on message sequence generation (`seq`), `packages/db/src/queries.ts:293-305`
**Problem**: `recordPromptMessage` calculates the next sequence number by running `coalesce(max(seq), 0) + 1` in a separate `SELECT` query before executing the `INSERT`.
**Why it matters**: Under concurrent traffic (e.g. parallel streaming chunks, rapid user inputs, or simultaneous agent tool calls in the same prompt thread), two concurrent calls will read the same maximum sequence number. The second insert will fail with a unique constraint violation on `prompt_messages_thread_id_seq_unique`.
**Suggested fix**: Compute `seq` atomically in the INSERT statement via a subquery, or serialize thread message inserts by locking the parent thread row (`SELECT id FROM prompt_threads WHERE id = ... FOR UPDATE`) inside a transaction.

### 🟠 Missing database indexes on foreign keys and frequently queried columns, `packages/db/drizzle/0000_same_vulcan.sql:1-126`
**Problem**: PostgreSQL does not automatically create indexes for foreign key columns. Essential query targets lack indexes: `snapshots.project_id` (used in `getProjectSnapshots` with `ORDER BY created_at DESC`), `deployments.snapshot_id` (used in `deleteSnapshot`), `prompt_threads.project_id` (used in `getProjectWithCurrentSnapshot`), `prompt_messages.snapshot_id`, and `projects.current_snapshot_id`.
**Why it matters**: Without an index on `snapshots(project_id, created_at desc)`, listing snapshot history performs a sequential scan over the entire `snapshots` table and sorts in memory. Additionally, cascading deletes on `projects` and `snapshots` will perform sequential scans across child tables, degrading performance and increasing lock times as data grows.
**Suggested fix**: Define composite or single-column indexes on `snapshots(project_id, created_at)`, `deployments(snapshot_id)`, `prompt_threads(project_id)`, and `prompt_messages(snapshot_id)` in the Drizzle schema and generate a migration.

### 🟠 `updatePromptMessage` crashes when called with no update fields, `packages/db/src/queries.ts:358-363`
**Problem**: If `updatePromptMessage` is called with only `{ id, userId }` (with `status`, `toolCalls`, and `snapshotId` all undefined), `updates` is `{}`. Drizzle ORM throws a runtime `Error: No values to set` when executing `.set({})`.
**Why it matters**: Callers invoking the update mutation without modified fields will crash with an unhandled 500 server error rather than receiving the unchanged record or a descriptive validation error.
**Suggested fix**: Check `if (Object.keys(updates).length === 0)` and either return the existing record immediately or throw a `ValidationError("No fields to update provided")`.

## Minor
### 🟡 `saveSnapshot` does not validate that `parentId` belongs to the same project, `packages/db/src/queries.ts:229-231`
**Problem**: When creating a snapshot with an optional `parentId`, `saveSnapshot` does not verify that the referenced parent snapshot belongs to `params.projectId`.
**Why it matters**: A caller can supply a snapshot ID belonging to another project or user, corrupting the project's commit lineage graph.
**Suggested fix**: When `params.parentId` is present, verify that a snapshot with that ID exists within `params.projectId`, throwing `NotFoundError` or `ValidationError` if it does not.

### 🟡 `getProjectSnapshots` lacks pagination parameters, `packages/db/src/queries.ts:155-190`
**Problem**: `getProjectSnapshots` returns all snapshot records for a project in a single query without `limit` or offset/cursor pagination.
**Why it matters**: For long-running projects with hundreds of prompt turns and snapshots, fetching all historical records at once increases memory usage and latency.
**Suggested fix**: Add optional `limit` and `cursor` (or `offset`) parameters, defaulting `limit` to a sensible page size (e.g. 50).

### 🟡 `saveSnapshot` allows arrays as `files` input and lacks file path validation, `packages/db/src/queries.ts:206-207`
**Problem**: The type check `typeof params.files !== "object"` evaluates to `false` for arrays (`typeof [] === "object"`). Additionally, individual file keys are not validated to ensure they are normalized relative paths without path traversal (`..` or leading `/`).
**Why it matters**: Passing an array or malformed file entries causes `computeSnapshotTreeHash` to throw an unhandled `TypeError` during `Buffer.byteLength(file.content)`. Furthermore, unnormalized paths can cause directory traversal issues when snapshots are unpacked in WebContainers.
**Suggested fix**: Add `Array.isArray(params.files)` to validation and sanitize file keys to ensure relative POSIX paths.

### 🟡 Top-level database pool instantiation on module import, `packages/db/src/client.ts:7-17`
**Problem**: `client.ts` initializes `postgres(connectionString, { max: 10 })` at the top level when the module is imported. Because `index.ts` re-exports `./client`, any module importing `@spark/db` (even for types, errors, or pure crypto utilities) instantiates a database client. Moreover, in production, it silently defaults to `localhost:5432` if `DATABASE_URL` is omitted.
**Why it matters**: Missing environment variables in production should fail fast at startup rather than falling back to localhost. Top-level side effects can also complicate testing and serverless deployments where connection pools must be scoped.
**Suggested fix**: Validate that `DATABASE_URL` is defined when `NODE_ENV === "production"`, and consider making the connection client lazily evaluated.

### 🟡 Usage of `any` in `DatabaseClient` type definition, `packages/db/src/queries.ts:28-29`
**Problem**: `export type DatabaseClient = PgDatabase<any, typeof schema, any>;` uses `any` twice with a Biome lint ignore comment.
**Why it matters**: `AGENTS.md` explicitly mandates: "Strict types enabled (no any); strict null checks across all packages."
**Suggested fix**: Replace `any` with Drizzle's generic HKT parameters (e.g. `PgQueryResultHKT`) or union the supported database and transaction client types.

### 🟡 `deleteSnapshot` does not protect deployments in `queued` or `building` states, `packages/db/src/queries.ts:571-579`
**Problem**: `deleteSnapshot` only checks if a deployment has `status === "active"`. Deployments with status `"queued"` or `"building"` are not checked.
**Why it matters**: Because `deployments.snapshotId` has foreign key `ON DELETE CASCADE`, deleting a snapshot that is currently queued or building will cascade-delete the deployment row mid-build.
**Suggested fix**: Expand the deployment conflict check to include statuses `"queued"`, `"building"`, and `"active"`.

## Nits
- ⚪ `packages/db/src/queries.ts:378-415`: `saveUserApiKey` accepts arbitrary provider strings without validating against the supported provider union (`openai`, `anthropic`, `gemini`, `groq`).
- ⚪ `packages/db/src/queries.ts:1-584`: No exported helper exists for creating prompt threads (`createPromptThread`); tests were forced to bypass `queries.ts` and import the table definition directly.
- ⚪ `packages/db/src/crypto.ts:86-124`: `extractKeyHint` for 9-10 character keys reveals 7 characters (first 3 and last 4), exposing most of the key if short vendor keys are used.
- ⚪ `packages/db/src/migrate.ts:11-16`: `runPostgresMigrations` does not document or enforce that the postgres connection pool should be configured with `{ max: 1 }`, which Drizzle requires to prevent migration lock deadlocks.

## Strengths
- **Robust envelope encryption**: `packages/db/src/crypto.ts` implements textbook AES-256-GCM encryption with 12-byte cryptographically secure random IVs, 16-byte authentication tags, and tamper verification (AC-2).
- **TOAST-safe snapshot projections**: `getProjectSnapshots` deliberately projects away the heavy `files` JSONB column, protecting database memory and network bandwidth from large virtual file tree de-serializations (AC-3).
- **Deterministic content addressability**: `computeSnapshotTreeHash` canonicalizes file path ordering and formats delimiters to produce deterministic SHA-256 tree hashes regardless of object insertion order.
- **Strong test foundation**: Integration tests in `packages/db/src/queries.test.ts` execute real migrations and queries against an in-memory PGlite instance, thoroughly validating tenant ownership isolation and error class contracts.

## Test coverage
The test suite in `packages/db` covers 41 tests across 5 test files with clean execution on PGlite. It covers happy paths, cryptographic tamper verification, cascading deletions, and authorization failures for project access and deployments. However, several critical failure paths are untested:
- Empty update payloads in `updatePromptMessage` (which crashes at runtime).
- Empty string `customDomain` collisions in `createDeployment`.
- Cross-project parent snapshot validation in `saveSnapshot`.
- Unauthorized forking of private projects in `createProject`.
- Concurrent sequence allocation in `recordPromptMessage`.
