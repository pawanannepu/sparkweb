## Summary
This change establishes the initial vertical slice for the core generation loop and live preview. It connects the builder workbench to an in browser WebContainer runner through an isolated iframe, streams planning tasks and file operations, and commits generated snapshots directly to PostgreSQL. The overall architecture and test foundation are solid, but four major issues around authentication header trust, sandbox path traversal, missing real model provider invocation, and stream cancellation state need resolution before merge.

## Major
### 🟠 Unauthenticated user spoofing via unvalidated x-user-id header, `apps/web/src/lib/auth.ts:102`
**Problem**: The `getCurrentUser` helper reads `req.headers.get("x-user-id")` directly without verifying an authenticated session token, signature, or cookie.
**Why it matters**: Any external client can pass an arbitrary `x-user-id` header to impersonate another user, bypass project ownership checks, and generate code or inspect snapshots on projects belonging to other accounts.
**Suggested fix**: Gate `x-user-id` header evaluation behind a development or test environment check, and resolve authenticated users in production through signed session tokens or session cookies.

### 🟠 Sandbox path traversal in virtual file updates and removal, `packages/sandbox/src/runner.ts:129`
**Problem**: The file update and delete methods clean paths using only `.replace(/^[./]+/, "")`, which strips only leading dots and slashes. Paths containing directory traversal segments such as `src/../../file` are not rejected.
**Why it matters**: Violates the key security invariant in Spec 0004 requiring strict path safety. A prompt tool call specifying relative traversal segments could write or delete files outside the project root directory inside the WebContainer virtual file system.
**Suggested fix**: Validate every incoming file path against a strict normalization check that rejects any path segment containing `..` or leading outside the sandbox workspace root.

### 🟠 Model provider execution is bypassed in favor of hardcoded templates, `apps/web/src/app/api/projects/[id]/generate/route.ts:198`
**Problem**: The route validates and decrypts provider keys for Anthropic, OpenAI, and Gemini, but the async generation pipeline never calls the AI SDK model providers. Instead, it runs hardcoded prompt keyword checks and returns prewritten template files.
**Why it matters**: Users supplying their own API keys will not receive actual AI generated code matching their prompts. The pipeline behaves as a static mock rather than an autonomous code generation loop.
**Suggested fix**: Wire the decrypted provider API key to the AI SDK Core streaming functions when not running in mock mode, streaming dynamic tool calls for file writing and deletion.

### 🟠 Stream cancellation does not mark the prompt message as failed, `apps/web/src/app/api/projects/[id]/generate/route.ts:181`
**Problem**: The route catches stream write errors in `sendEvent` and swallows them without setting cancellation state. The loop only checks cancellation immediately after the planning stage, so aborting during file streaming allows execution to continue to `saveSnapshot` and marks the assistant message as completed.
**Why it matters**: Violates AC-6, which requires cancelled generations to halt immediately and record a failed message status with cancellation metadata. Aborted runs erroneously appear as successful completions in database records.
**Suggested fix**: Verify `req.signal.aborted` throughout the streaming loop, avoid swallowing stream write failures, and update the prompt message status to failed with a cancellation reason when the client disconnects.

## Minor
### 🟡 Streamed text chunk events are dropped by the client hook, `apps/web/src/hooks/useGenerationLoop.ts:126`
**Problem**: The server emits `event: text` chunks with turn explanations, but `useGenerationLoop` only processes `plan`, `file_op`, `finish`, and `error` events.
**Why it matters**: Text explanations and reasoning generated by the model are never forwarded to the UI, leaving the chat assistant message empty until the final finish event.
**Suggested fix**: Add an event listener branch for `text` in `useGenerationLoop` to collect text chunks and surface them to the chat panel.

### 🟡 Sandbox runner uses wildcard target origin and lacks origin verification, `apps/web/src/app/sandbox/runner/page.tsx:34`
**Problem**: The sandbox runner transmits messages to `window.parent` with `*` target origin and does not check `event.origin` when receiving messages.
**Why it matters**: Any parent frame embedding the runner could send commands or receive internal log streams and diagnostic messages.
**Suggested fix**: Restrict `postMessage` target origin to `window.location.origin` and verify `event.origin` in `handleMessage` before executing commands.

### 🟡 Snapshot file size limits are not enforced, `packages/sandbox/src/template.ts:210`
**Problem**: The snapshot exclusion helper filters by path patterns but does not enforce the 500KB per file or 10MB total tree limits specified in Spec 0004.
**Why it matters**: Extremely large files or binaries could be persisted directly into PostgreSQL `snapshots.files` JSONB fields, increasing database storage footprint.
**Suggested fix**: Validate individual file size and aggregate tree size in `filterSourceFiles` or `saveSnapshot`, throwing a validation error if limits are exceeded.
