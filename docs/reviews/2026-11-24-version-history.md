## Summary
Feature 8 adds `project_branches`, branch and snapshot lineage columns, cursor paginated snapshot listing, jsdiff based server comparison, forward rollback mutations, and client history/diff/branching components across `packages/shared`, `packages/db`, and `apps/web`. Type checking (`pnpm check-types`), linting (`pnpm lint`), unit tests (`pnpm test`, 37 files and 225 tests), and production build (`pnpm build`) all pass, and the snapshot metadata projection cleanly avoids loading `files` JSONB on timeline lists. However, merge must wait due to four blockers: hardcoded `isStreaming: false` in the workbench page disables streaming locks and breaks auto save, multi step DB mutations lack transactions and return stale `activeBranch.headSnapshotId` on rollback, unvalidated IDs and cursors trigger HTTP 500 database errors, and creating an immediately active branch leaves old files loaded while branch timelines hide ancestor commits. Split diff rendering, missing error/confirmation UI, inspect mode input leaks, missing DB indexes, and thin test coverage on new endpoints and hooks also need resolution.

## Blockers
### 🔴 Hardcoded `isStreaming: false` disables streaming locks and corrupts auto save, `apps/web/src/app/page.tsx:118`
**Problem**: `BuilderPage` passes literal `isStreaming: false` to both `useProjectFiles` (`apps/web/src/app/page.tsx:118`) and `useVersionHistory` (`apps/web/src/app/page.tsx:129`), while the live `isStreaming` flag is only destructured afterward from `useGenerationLoop` at `apps/web/src/app/page.tsx:190` and never wired back into those hooks. Meanwhile, `onFileChange` at `apps/web/src/app/page.tsx:206` calls `updateFileContent` for every streamed AI file.
**Why it matters**: Client side rollback conflict protection (`useVersionHistory.ts:271`), inspect entry blocking (`useVersionHistory.ts:230`), canvas inspector locking, and auto save cancellation (`useProjectFiles.ts:83` to `95`) never trigger during active AI generation. Worse, `updateFileContent` marks `hasUnsavedCanvasChanges` as `true` during AI streaming and schedules a spurious `"canvas"` snapshot POST three seconds after streamed edits because `useProjectFiles` thinks streaming is inactive.
**Suggested fix**: Lift streaming state via a shared state hook or `useRef` passed into `useProjectFiles` and `useVersionHistory` (updating when `useGenerationLoop` reports `isStreaming`), and use a dedicated helper on `useProjectFiles` for incoming AI stream file syncs that does not arm the `"canvas"` auto save timer.

### 🔴 Non atomic snapshot and branch mutations plus stale rollback branch head, `packages/db/src/queries.ts:765`
**Problem**: `saveSnapshot` (`packages/db/src/queries.ts:373` to `490`), `rollbackSnapshot` (`packages/db/src/queries.ts:765` to `900`), `createBranch` (`packages/db/src/queries.ts:558` to `643`), `switchBranch` (`packages/db/src/queries.ts:645` to `711`), `deleteBranch` (`packages/db/src/queries.ts:713` to `756`), and `createProject` (`packages/db/src/queries.ts:87` to `123`) execute separate read, insert, and update queries outside `db.transaction(...)` and without row locking (`SELECT ... FOR UPDATE`). Furthermore, inside `rollbackSnapshot`, `activeBranch` is fetched at lines 814 to 820 before `projectBranches.headSnapshotId` is updated at lines 873 to 879 without `.returning()`, so line 898 returns the pre rollback `headSnapshotId` (serialized directly at `apps/web/src/app/api/projects/[id]/snapshots/rollback/route.ts:75`). Additionally, `saveSnapshot` overwrites `projects.activeBranchId` at lines 480 to 487 even when an explicit `params.branchId` differs from the active branch, and `POST /api/projects/[id]/snapshots` (`route.ts:152`) sets `parentId` from `project.currentSnapshotId` outside any lock.
**Why it matters**: This violates the key transaction invariant in `docs/specs/0007-version-history-snapshots-and-time-travel-rollback/index.md:117` (`AC-7`) and causes stale or conflicting `headSnapshotId`, `currentSnapshotId`, and `parentId` pointers under concurrent requests (such as an overlapping auto save and rollback, or starting a stream right as `checkActiveGeneration` completes). Callers of `rollbackSnapshot` receive an outdated `activeBranch.headSnapshotId`.
**Suggested fix**: Wrap `saveSnapshot`, `rollbackSnapshot`, `createBranch`, `switchBranch`, `deleteBranch`, and `createProject` in `db.transaction(...)`, lock the target `project_branches` or `projects` row with `.for("update")`, resolve `parentId` from the locked branch head, update `projects.currentSnapshotId` only when the target branch is `projects.activeBranchId`, and capture `.returning()` from the `projectBranches` update in `rollbackSnapshot`.

### 🔴 Unvalidated UUIDs, cursors, and query limits trigger 500 database errors, `packages/db/src/queries.ts:266`
**Problem**: None of the dynamic route parameters (`id`, `snapshotId`, `branchId` across `snapshots/route.ts`, `snapshots/[snapshotId]/route.ts`, `snapshots/[snapshotId]/diff/route.ts`, `snapshots/rollback/route.ts`, `branches/route.ts`, `branches/[branchId]/route.ts`, `branches/[branchId]/switch/route.ts`), optional query params (`branchId` in `snapshots/route.ts:30`, `baseId` in `diff/route.ts:21`), or body fields (`rollbackSchema.snapshotId` in `rollback/route.ts:16`, `createSnapshotSchema.branchId` and `restoredFromSnapshotId` in `snapshots/route.ts:76` and `79`) validate UUID format with `z.string().uuid()`. In `snapshots/route.ts:32` and `33`, `Number.parseInt(rawLimit, 10)` produces `NaN` for non numeric input (`limit=abc`), sending `NaN + 1` into PostgreSQL `.limit(...)`. In `getPaginatedSnapshots` (`packages/db/src/queries.ts:268` to `273`), any base64 JSON cursor containing truthy non ISO `createdAt` or non UUID `id` strings is passed directly into `${parsed.createdAt}::timestamp` and `${parsed.id}::uuid`. Every route `catch` block also returns raw `errorObj.message` in `500` responses.
**Why it matters**: Any malformed UUID, non numeric `limit`, or corrupted/forged cursor causes PostgreSQL cast errors (`22P02`, `22007`, or invalid limit), crashing requests with HTTP `500` and leaking database internals back to clients.
**Suggested fix**: Validate all route params, query IDs (`branchId`, `baseId`), and body UUIDs with `z.string().uuid()` (returning `400` or `404`), validate `limit` with Zod integer bounds (`1` to `100`), validate decoded cursor payloads with Zod (`.datetime()` and `.uuid()`, returning `400` or ignoring malformed fields safely), and omit `errorObj.message` from `500` JSON payloads.

### 🔴 New active branch leaves stale editor files and shows empty history, `apps/web/src/hooks/useVersionHistory.ts:172`
**Problem**: In `createNewBranch` (`useVersionHistory.ts:172` to `202`), when `switchActive` is `true` (the default in `CreateBranchDialog.tsx:32`), the server updates `projects.activeBranchId` and `projects.currentSnapshotId` (`queries.ts:631` to `640`) and `POST /api/projects/[id]/branches` returns only `{ branch }` without `files`. The client updates `branches` and `snapshots` (`useVersionHistory.ts:190` to `193`), but never fetches the branch head files, never calls `onBranchSwitched`, and never exits inspect mode if branching was initiated from `InspectModeBanner`. Compounding this, `getPaginatedSnapshots` filters solely by `eq(snapshots.branchId, params.branchId)` (`queries.ts:281`), whereas `createBranch` (`queries.ts:617` to `624`) only stores `headSnapshotId` on `project_branches` without copying or linking ancestor commits whose `branchId` belongs to the source branch.
**Why it matters**: Creating a branch from an older historical snapshot switches `activeBranchId` to the new branch while leaving the editor, `useProjectFiles`, and the WebContainer runner holding the previous branch or inspect files; the next canvas edit auto saves the wrong file tree onto the new branch. In addition, the drawer timeline for the new branch renders completely empty (`[]`) until a new snapshot is created, hiding all inherited history up to `headSnapshotId` (failing `AC-4`).
**Suggested fix**: When `switchActive` is `true`, either return `{ branch, files, currentSnapshotId }` from `POST /api/projects/[id]/branches` (or call `switchBranch` after creation), exit inspect mode, and invoke `onBranchSwitched(files, branch)` so `useProjectFiles` and WebContainer reload the branch head tree. On the backend, query branch history either by walking `parentId` from `project_branches.headSnapshotId` (via recursive CTE) or recording branch ancestry so newly branched timelines include commits up to the branch point.

### 🟠 Branch switcher is empty before drawer opens and drawer open triggers duplicate fetches, `apps/web/src/hooks/useVersionHistory.ts:114`
**Problem**: `fetchBranches()` is only triggered inside `useEffect` when `isDrawerOpen` becomes `true` (`useVersionHistory.ts:114` to `120`), so the header `BranchSwitcher` never loads branches on initial page mount and renders `branches = []` until the user opens the drawer. ### 🟠 Missing database indexes and cursor timestamp truncation hazard, `packages/db/src/schema/snapshots.ts:32`
**Problem**: `packages/db/drizzle/0001_ancient_doctor_strange.sql` and the Drizzle schemas (`snapshots.ts:32` to `57`, `project-branches.ts:6` to `21`) define no B tree indexes supporting the new queries: `getPaginatedSnapshots` filters and orders by `(project_id, branch_id, created_at DESC, id DESC)`, `getProjectBranches` filters/orders by `(project_id, created_at)`, and `checkActiveGeneration` joins `prompt_messages` and `prompt_threads` filtering `(thread_id, status)`. In addition, `getPaginatedSnapshots` encodes `lastItem.createdAt.toISOString()` (`queries.ts:314`), truncating PostgreSQL microsecond `timestamp` values to millisecond resolution while comparing against `timestamp` (without time zone) via `${parsed.createdAt}::timestamp` (`queries.ts:272`).
**Why it matters**: Queries degrade to sequential scans as snapshots and messages grow. More immediately, millisecond truncation plus `toISOString()` `"Z"` suffix cast to timezone naive `timestamp` can cause cursor boundary rows to be duplicated or skipped when consecutive snapshots fall within the same millisecond or when the database session timezone is not UTC.
**Suggested fix**: Add a migration creating composite indexes on `snapshots (project_id, branch_id, created_at DESC, id DESC)`, `snapshots (project_id, created_at DESC, id DESC)`, `project_branches (project_id)`, and `prompt_messages (thread_id, status)`, and serialize cursors with exact timestamp precision (or use `timestamptz` consistently and pass a `Date` parameter via Drizzle rather than a raw string cast).
